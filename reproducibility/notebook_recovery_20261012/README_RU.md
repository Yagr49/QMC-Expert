## Что подтверждено сохранёнными выводами

В майском `descriptors_and_embeddings_comparison_with_labels`, ячейка 20
(индексация с нуля), сохранены следующие endpoint R²:

| Вариант | Sa MIC | Sa MBC | Ec MIC | Ec MBC |
|---|---:|---:|---:|---:|
| Human contrastive + categorical task_id | 0.7102 | 0.6403 | 0.4269 | 0.7394 |
| Human contrastive + OpenAI class vectors | 0.7494 | 0.6752 | 0.5918 | 0.7708 |
| Первый вариант в Table 1/2 v5 | 0.71 | 0.64 | 0.43 | 0.74 |
| Второй вариант в Table 1/2 v5 | 0.75 | 0.68 | 0.60 | 0.77 |

Семь из восьми значений совпадают при округлении до двух знаков. Для Ec MIC
текстового варианта сохранено 0.5918: обычное округление даёт 0.59, а не 0.60.
Соответствующие endpoint RMSE в выводе этой ячейки не напечатаны, хотя код их
рассчитывает. Это находка происхождения R², не полное воспроизведение всех RMSE
и всех количественных моделей Table 2.

Ячейки 18–20 делят строки «молекула × задача», со стратификацией по task_id.
Подпись one-hot в статье не вполне соответствует именно найденному варианту:
в ячейке 20 task_id передаётся CatBoost как категориальный признак. Ноутбук также
содержит другие варианты разбиения в предыдущих ячейках; их результаты отличаются.
Часть поздних ячеек не исполнена. При связывании чисел с кодом нужно учитывать,
что сохранённый код мог редактироваться после последнего исполнения ячейки.

В `causal_final`, ячейка 7, сохранены OOD RMSE:
raw = 2.314, human = 2.189, regression = 2.276.
Именно здесь находится функция boot_delta_rmse, которая для каждого bootstrap
вычисляет sqrt(mean(a²)) − sqrt(mean(b²)); она действительно оценивает ΔRMSE.
Числа её вывода совпадают с существующим analysis/ablation_bootstrap.csv.
В CSV сохранено среднее bootstrap-разниц, а не точная разница исходных RMSE.
Функция пересэмплирует отдельные endpoint-остатки, не кластеры молекул.

В июльском `shap_causal_analysis`, ячейка 7, сохранено regression = 2.133
при raw = 2.314 и human = 2.189. Поэтому 2.13 имеет найденный источник и не
должно исправляться на 2.27 только на основании майского bootstrap CSV.
Это два архивных расчёта с разными результатами regression-варианта.

Апрельский подбор лучшего seed — отдельная подтверждённая особенность кода;
при использовании его выбранного test для оценки качества нужна независимая
проверка после выбора. Его прямое участие в числах Table 1/2 пока не установлено.

## Указатель и проверка файлов

- `inventory.csv` — все источники, даты, пути восстановленных копий и SHA-256.
- `manifest.json` — происхождение и сохранённые метрические выводы.
- `metric_outputs.json` — текст результатов из выбранных ноутбуков с номерами ячеек.
- `article_number_provenance.csv` — сопоставление восьми human multitask R² и трёх июльских OOD RMSE с числами v5; совпадение после округления отмечено отдельно.
- `validation.json` — проверка чтения JSON, совпадения хешей копий и удаления обнаруженных ключей.
- `recover_notebooks.py` — воспроизводимый локальный скрипт восстановления; без сети и исполнения ноутбуков.
